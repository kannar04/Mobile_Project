# Feed and private libraries

Accepted F31 r7, planning context28. App remains native Java/XML. Main Home feed has cursor prefetch, a100-row window, server-acknowledged pull refresh and no More button. Explore/Tools primary entries use MainActivity Fragments. Contextual protected tasks keep their existing routes.

Adoption posts use managed `mediaApi/post`, additive schema6 and a community-only audience. They store listingId and exact content/publication versions, never copied private listing/contact fields. The function rechecks the existing F12 discovery policy, root listing, listing publication, pet, offer authority, activity gate and listing slot in the same transaction. It writes no protected adoption documents. Current listing reads revalidate through existing Rules. A missing, hidden, stale, held or foreign source cannot be turned into an adoption post; the source's publication workflow remains separately gated. Safe post hide/archive still works after source removal.

`users/{uid}/likedPosts/{postId}` is an own-only reference index. Canonical set_like, count delta, operation receipt and mirror change commit atomically. The like rule validates the entire operation; other affected-document rules link to that changed canonical reaction to stay within Firestore expression limits. Foreign/unbounded queries and forged/omitted mirrors are tested. Unlike remains available after source loss. The index contains no post body, profile payload, listing snapshot or image URL. Pets saved remains the unchanged F14 listing-interest namespace.

Indexes are additive: owner-filtered listingDiscovery selection plus a collection-group single-field index on likes.active for privileged migration. Current declarations are in canonical/selected indexes JSON. `firebase-tests/setup-feed-r7-indexes.cjs` verifies/creates only these requirements; it does not delete other indexes.

Run `backfill-liked-posts.cjs` from firebase-tests for a dry run, or `--apply` for approved owner maintenance using an existing Firebase CLI login and Node22.12+. It scans at most100 canonical active likes per invocation, resumes a private maintenance cursor, and rechecks the canonical reaction and exact successful receipt inside each write transaction. Concurrent Unlike cannot resurrect a reference. New app likes maintain the mirror immediately. No scheduler or embedded Admin credential is introduced. Current completion proof is in the planning evidence; privileged imported/unsupported legacy reactions must not be invented as verified likes.

Names/photos on other people's posts come from their currently permitted published profile. Private onboarding names/photos are never automatically published; hidden identities and guests keep the approved neutral identity. F31 r7 does not change that policy.

New namespace inventory: own likedPosts, private maintenance/likedPostMigration cursor, schema6 listing references in post/root/revision/member projection. Broader F43 account-closure orchestration, protected listing publication and durable image caching remain separate gates; this handoff does not claim those adapters complete. Storage/media limits and maintenance remain documented in MEDIA_STORAGE.md.
